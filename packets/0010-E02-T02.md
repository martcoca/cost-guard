# T02: The guard must survive a real plan

- **Initiative:** 0010 — Cost Guard
- **Epic:** E02 — a consumer cannot be silently behind
- **Packet id:** `0010-E02-T02`
- **Executor:** `worker`
- **Target:** The `cost-guard` repository
- **Approval:** none
- **Shape:** `execution`
- **Status:** not started
- **Source:** initiatives/0010-cost-guard/E02-staleness/T02-guard-scales-with-its-input.md

## Context

`cost-guard@v1.0.0` — released, and consumed by `platform-aws`, `platform-gcp` and
`platform-azure` — **hangs on a 47 KB OpenTofu plan.** Measured: over 45 seconds with no
output, killed at 60. It is instant on the fixtures in its own suite.

The cause is one line:

```bash
if [[ -z "${plan_input//[[:space:]]/}" ]]; then
```

A bash global substitution across the whole plan string. Bash performs this character by
character and it degrades sharply with length. The fixtures are a few hundred bytes; a real
CloudFront plan is fifty thousand.

**The line that hangs is the empty-input guard** — the one added so the tool would fail
closed rather than report a missing plan as clean. The safety check is what makes it unsafe
on real input, which is worth sitting with before writing the replacement.

**How this presents in CI, and why nobody caught it:** not as a failure. The `guarded-plan`
job sits until the job timeout, looks like a stalled runner, and burns metered minutes doing
nothing. Found by applying real infrastructure, not by any test.

**The deeper defect is the suite, not the line.** Every negative case it has is about
*content* — denied type, clean plan, errored plan, empty input, unparsable input. **Not one
is about size.** A guard's inputs grow with the infrastructure it guards, and nothing in its
suite grows with them.

## Goal

The guard reaches a verdict on a realistically-sized plan in a time a CI job would tolerate,
and its suite would have caught this.

## Boundary

**Do not change the exit contract.** 1 for a denied create, 0 for a clean plan, 2 for
anything undecidable. That contract is the product.

**Do not weaken the empty-input check.** It exists because "no denied resources" and "no
plan" must not produce the same verdict, and that reasoning is untouched by its being slow.
Replace how it is computed, never whether it happens.

Do not change the denylist. Do not touch the freshness action from T01.

**Do not release.** Tagging is publication and is not yours. Prepare it, demonstrate it,
and say what version it should be.

## Done when

- The guard reaches a correct verdict on a **realistically-sized plan** — at least 50 KB,
  built from real OpenTofu output rather than padding — in **under five seconds**.
- **A size-based regression test exists** and is part of the suite, so this cannot return
  quietly. It must fail against the current implementation: demonstrate that.
- **Every existing exit-contract case still passes**, unchanged. 1/0/2 across denied,
  clean, errored, unrecognizable and empty input.
- **Empty and whitespace-only input still exit 2.** Prove it with the new implementation,
  because that is the check being rewritten.
- `scripts/test-suite-can-fail.sh` still proves the suite reacts to a broken denylist and a
  softened fail-closed path.
- The evidence names **what version this should be released as** and what the three
  consumers must do to pick it up — T01's evidence already established that propagation is
  a pin bump in each.

## Check

From the repository root:

```bash
scripts/test-cost-guard.sh
scripts/test-suite-can-fail.sh
```

Then the demonstration, with output in the pull request:

1. **Time the current implementation** against a ≥50 KB plan. Show it hanging or timing out.
2. **Time the fixed implementation** against the same plan. Show the verdict and the seconds.
3. **Show the new size test failing** against the old implementation and passing against the
   new one. A regression test that never failed is not a regression test.
4. Show the full 1/0/2 contract intact.
5. Show empty and whitespace-only input still exiting 2.

## Notes

A ≥50 KB plan is easy to obtain honestly: `tofu show -json` on any stack with a CloudFront
distribution or a comparable resource produces one. **Do not synthesize it by repeating a
string** — a pathological case built from repetition may not resemble the real input that
found this.

If you find other operations in the guard with the same shape — string rewriting over the
whole input rather than streaming or delegating to `jq` — report them even if they are not
currently slow enough to matter. The next resource type is larger than this one.

Write `evidence/0010-E02-T02.md`.
