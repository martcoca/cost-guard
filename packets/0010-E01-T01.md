## Context

`scripts/cost-guard.sh` and `config/cost-guard-denylist.json` exist as byte-identical
copies in `platform-aws`, `platform-gcp`, and `platform-azure`. Keeping them identical has
already required merging the same change into two repositories by hand.

The guard reads OpenTofu plan output — both `tofu show -json` (one document with a
`resource_changes` array) and `tofu plan -json` (a stream of `planned_change` events) — and
fails on any create of a denied resource type. It **fails closed**: empty input, an errored
plan, and unrecognizable input all exit 2 rather than passing, because "no denied
resources" and "no plan" must not produce the same verdict.

`platform-azure` carries the best tests: `scripts/test-cost-guard.sh` asserts the exact
exit contract, and `scripts/check-denylist-agreement.sh` has a negative case proving it can
fail. Those are the versions to port.

**Where the sources are.** The three platform repositories are checked out as siblings of
this one, so they are reachable at `../platform-aws`, `../platform-gcp`, and
`../platform-azure`. The four files to read:

| File | Take from |
|---|---|
| `scripts/cost-guard.sh` | any of the three — verified byte-identical |
| `config/cost-guard-denylist.json` | any of the three — verified byte-identical |
| `scripts/test-cost-guard.sh` | `../platform-azure` |
| `scripts/check-denylist-agreement.sh` | `../platform-azure` |

If a sibling is missing, stop and say so rather than reconstructing a denylist from memory.
A denylist that is *nearly* right is worse than no guard, because it will be trusted.

This packet works entirely inside the new repository. It changes no platform repository —
that is T02, and its shape depends on the interface chosen here.

## Goal

The `cost-guard` repository holds the only implementation of the guard and the denylist,
with a tested interface another repository's CI can consume without copying either file.

## Boundary

**Move, do not improve.** The guard's behavior and the denylist's contents transfer
unchanged. A behavioral change made in the same commit as a move is indistinguishable from
a regression when something later fails.

Do not touch `platform-aws`, `platform-gcp`, or `platform-azure`. Do not touch Azure Policy
or anything in `docs/decisions/`.

Do not add a denied type, remove one, or adjust a price string.

## Done when

- The repository contains `cost-guard.sh` and `cost-guard-denylist.json`, byte-identical to
  the current platform copies.
- **A consumption interface exists and is documented**, chosen from: a reusable GitHub
  Actions workflow, a composite action, or a digest-verified fetch of a tagged release. The
  README states which was chosen and why the two rejected options were rejected.
- The interface is demonstrated working from a *different* repository — a scratch fixture
  repository or a test workflow is acceptable; a claim is not.
- `test-cost-guard.sh` is ported and asserts exit `1` for a denied create, `0` for a clean
  plan, and `2` for errored, unrecognizable, and empty input.
- CI runs the suite on every push, and includes a case proving the suite itself can fail.
- The README states the fail-closed contract explicitly, because a future reader who does
  not know it will "simplify" it away.

## Check

From the repository root, with no cloud authentication:

```bash
scripts/test-cost-guard.sh                       # exits 0; asserts 1/0/2 across six inputs
bash -n scripts/cost-guard.sh                    # parses
scripts/cost-guard.sh tests/fixtures/plan-with-nat.json;      test $? -eq 1
scripts/cost-guard.sh tests/fixtures/plan-clean.json;         test $? -eq 0
scripts/cost-guard.sh tests/fixtures/plan-errored.jsonl;      test $? -eq 2
: > /tmp/empty.json && scripts/cost-guard.sh /tmp/empty.json; test $? -eq 2
```

Then the part that is easy to skip and is the actual point:

```bash
diff <(jq -S . cost-guard-denylist.json) \
     <(jq -S . ../platform-aws/config/cost-guard-denylist.json)   # identical
diff <(jq -S . cost-guard-denylist.json) \
     <(jq -S . ../platform-gcp/config/cost-guard-denylist.json)   # identical
diff <(jq -S . cost-guard-denylist.json) \
     <(jq -S . ../platform-azure/config/cost-guard-denylist.json) # identical
```

And the interface, exercised from outside this repository. Capture the run URL or the
command output in the pull request. **An interface that has only been reasoned about has
not been demonstrated.**

## Notes

Read the exit codes from the guard itself, not from a pipeline. `cmd | head` reports
`head`'s status, which has already produced a wrong conclusion in this organization once.

Report which interface you chose and what it cost you. If a reusable workflow turned out to
be awkward for a shell script, that is a finding worth more than a clean result.
