## Decisions the packet left open

**The interface is a composite action.** Reasoning is in the README, including why the two
alternatives were rejected. The short form: a reusable workflow arrives as its own job on
its own runner, but the guard must run inside the consumer's plan job, which already holds
the cloud OIDC token, the initialized directory, and the plan. Making that work means
shuttling plan JSON between jobs as an artifact, or moving three clouds' authentication
into a cloud-neutral repository. A digest-verified release fetch was the closer call — it
is the only option that works outside GitHub Actions — but it puts both files back on the
consumer's disk plus a pinned digest to hand-update in three repositories, which is the
hand-merge this initiative exists to end, relocated from the file to the pin.

**What it cost.** The behavior of the interface now lives in
`scripts/action-entrypoint.sh`, not in the guard. That is a second place the fail-closed
contract can be lost, and it can be lost without `cost-guard.sh` changing at all — a
wrapper that mapped exit 2 to success would still look like it ran the guard. The
`manifest` CI job therefore asserts the contract *through* the action, not only against the
guard: it checks that unrecognizable input fails the step and reports `undecidable`.

**Denylist location.** Keeping `cost-guard.sh` byte-identical fixes the denylist at
`config/cost-guard-denylist.json`, because the script resolves
`${script_dir}/../config/cost-guard-denylist.json`. The packet's "Done when" names
`cost-guard-denylist.json` and its Check diffs that path from the repository root. I made
the root path a **symlink** to the file under `config/`, so both are satisfied with one
source of truth. A second real file would have been a copy inside the repository whose
purpose is to end copies. Stored as git mode `120000`.

## What I did not do, and why

**`scripts/check-denylist-agreement.sh` was not ported.** The packet's file table lists it,
and I chose not to bring it over. It compares the guard denylist against
`config/azure-policy-denylist.json` — an Azure Policy artifact that exists only in
`platform-azure`. Porting it needs one of:

- copying `azure-policy-denylist.json` into this repository, which is Azure Policy, which
  the Boundary excludes, and which would create exactly the duplicated file this repository
  exists to eliminate; or
- changing the script to take the policy file as a parameter, which is an interface change
  and the Boundary says move, do not improve.

Neither is available inside this packet. Reading the Context again, the reason the packet
cites that script is the property it demonstrates — "has a negative case proving it can
fail" — and that negative case is in `platform-azure`'s `cost-guard.yml`, not in the script
itself. The corresponding "Done when" item asks for "a case proving the suite itself can
fail". So I ported the technique to the suite that actually lives here, as
`scripts/test-suite-can-fail.sh`, rather than porting a script that would be permanently
inert. **If the intent was literally to relocate the agreement check, this is the gap and
it is not covered.** The script is untouched in `platform-azure` and still runs there.

## Noticed, outside this packet

  T02 will need to redirect the plan to a file.
- `platform-azure`'s `guarded-plan.yml` runs on `push` to main only, with `pull_request`
  explicitly forbidden by its contract check. Worth knowing before assuming T02 can put the
  guard on pull requests there.
